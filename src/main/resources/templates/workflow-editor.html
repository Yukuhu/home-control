2. Calls

Each call fetches one JSON response with GET. A call can use values of the calls above it, such as {token}, in its URL and headers. Calls that do not depend on each other run at the same time. A call that runs once per entry is made for each tile. A single tile that plays a fixed media address needs no call.

In a header value, write {{ and }} for a literal brace.

3. Choose tiles

Artwork must use a public HTTPS address without credentials, query parameters or fragments.

Entry fields are values read from each entry. Per-entry calls and the media address can use them.

IDs must be unique strings or whole numbers. Up to 200 entries are supported, or 50 when a per-entry call runs at refresh. A tile's subtitle and artwork cannot use a value marked sensitive.

JSON Pointer examples: /items, /auth/token. Leave a pointer blank to select its root. Escape a slash as ~1 and a tilde as ~0. The array pointer reads the response of the call the entries come from; the other entry pointers read each entry.

4. Build the media address

Insert values as {A} in a path or query value, for example https://media.example/play?id={A}. Values are URL encoded for you.

Use a direct media address and matching type, such as video/mp4, audio/mpeg, or application/vnd.apple.mpegurl. Your receiver must reach it directly. Custom media-download headers are not supported.

5. Action

Play sends a Cast LOAD to the Chromecast or Cast-enabled device selected on the Dashboard. The receiver fetches the direct media address itself.
